# P2 Deliverables: Methods §3.1

## Methods §3.1: Data and Preprocessing

We used the original CIC-IDS2017 dataset for the main benchmark and its corrected version for dataset sensitivity analysis. Both versions were processed independently using the same feature and partitioning policies, since changes in labels and flow construction preclude treating their records as paired observations. The task was binary detection: benign traffic was labelled 0 and attacks 1, while fine-grained attack families were retained as evaluation metadata. Corrected labels ending in “attempted” were mapped to benign under the declared behavioural detection policy, with their original labels and subgroup flags preserved. The shared input schema comprised 75 numerical flow statistics and destination port. All methods used identical records and preprocessing parameters within each dataset version and partitioning protocol, so differences in data preparation would not confound the comparison.

Feature exclusion addressed several distinct shortcut risks. Flow ID was excluded wherever present because it encodes connection identity and can enable memorisation of sessions. Source and destination IP addresses were excluded because they identify experimental hosts, including attackers and victims, allowing models to exploit the laboratory topology. Timestamps and capture-day information were used only for partitioning and auditing, then excluded from model inputs because capture schedules can reveal when particular attacks occurred. Labels, attack-family identifiers, row identifiers, and grouping keys were likewise isolated from the feature matrix. Destination port was retained because service identity can help distinguish traffic behaviour, although scheduled attacks against particular services may make it a shortcut. A matched port-removal ablation therefore used the same records, partitions, numerical transformations, and labels to assess dependence on service identity.
<!-- Sources: docs/feature_dict.md; docs/split_report.md; docs/preprocess_report.md. -->

The main experiment used group-constrained stratification by attack family, targeting training/validation/test proportions of 70%/15%/15% with seed 42. Stratification supported comparisons across common and rare attack families, while grouping prevented identical numerical records from crossing partition boundaries. Groups were defined by exact equality across the 75 numerical fields, excluding destination port so that the same protection also applied to the ablation. Conflicting labels within a group were retained without majority relabelling. After standardisation and float32 conversion, numerical inputs were checked again because distinct source values can become identical at reduced precision. Such overlaps were removed from later partitions, prioritising training, then validation, then testing, without consulting labels or model scores. Final original-data counts were 1,764,265/367,036/346,544, giving 71.20%/14.81%/13.99%. These are the actual proportions after overlap removal; 70%/15%/15% remained the initial target. Evaluation therefore concerns retained samples.

A secondary temporal check trained on 3–5 July 2017, validated on 6 July, and tested on 7 July. This assessed transfer to later traffic, including attack families absent from training, under a different distribution from the random main experiment. Numerical-feature groups recurring across dates were removed from later partitions without moving future records into earlier sets; the float32 overlap check also applied. For both protocols, scaling statistics, port vocabularies, and binary class weights were fitted exclusively on the corresponding training set. The 64 most frequent training ports and an OTHER category were one-hot encoded, yielding 140 inputs; the ablation retained 75. Validation and test sets were not balanced by resampling. Shared saved indices, preprocessing parameters, and file hashes made the protocol reproducible.
