# P3 Deliverables: Methods §3.2 and Table 3 Explanation

## Methods §3.2: Evaluation Protocol

We evaluate network intrusion detection through five complementary layers because no single score captures detection quality, operational usefulness, and computational cost. All methods use shared data partitions and preprocessing, with benign traffic labelled zero and attacks labelled one. Higher scores indicate greater attack suspicion. Evaluation retains the observed test distribution, without resampling or applying training weights. Classification thresholds are calibrated exclusively on validation data and remain fixed during testing.

First, accuracy and binary Macro-F1 describe classification at a specified threshold. Accuracy can be dominated by benign traffic, allowing a detector that misses attacks to appear effective. Macro-F1 gives equal weight to benign and attack classes, reducing this dominance. However, it remains threshold dependent and treats all attacks as one class. Consequently, neither measure establishes whether rare attack families are detected or whether the resulting alert volume is manageable.

Second, ROC-AUC and precision–recall analysis assess score rankings across thresholds. ROC-AUC measures discrimination but does not directly express alert precision. When benign traffic is abundant, a small false positive rate can still produce many false alarms, making strong ROC performance insufficient evidence of operational usefulness. Precision–recall curves expose the trade-off between attack coverage and alert reliability. We summarise these curves using Average Precision (AP), rather than trapezoidal PR-AUC, and interpret AP alongside attack prevalence.

Third, operating-point evaluation addresses false alarm constraints relevant to security operations centres. We report empirical test ROC sensitivity at FPR limits of 0.1%, 1%, and 5%, selecting the highest observed TPR within each constraint without interpolation. These descriptive summaries are distinguished from frozen-threshold testing. For the latter, thresholds are calibrated using benign validation scores, with 1% and 5% targets, and applied unchanged to test scores. Actual test FPR and TPR are reported because validation targets need not transfer exactly. Hypothetical daily alert counts combine stated traffic volumes with these measured conditional rates.

Fourth, attack-family recall reveals failures hidden by aggregate measures. For each family, we report the number of attacks detected and its sample support. This evaluates binary detection within each family, without requiring multiclass predictions. Small supports limit interpretation, while absent families receive undefined recall rather than zero. Binary Macro-F1 cannot replace this analysis because it does not assign equal weight to individual attack families.

Fifth, training time, inference latency, and throughput describe computational cost. CPU inference measurements specify hardware, batch size, thread settings, warm-up, and repetitions. Median batch time excludes loading and metric computation. Dividing this time by batch size gives amortised time per flow, not individual request latency. Comparisons require matching measurement conditions.

Across five training seeds, results are summarised by their mean and sample standard deviation. Paired comparisons align predictions by test row identifiers and use class-stratified bootstrap resampling to estimate percentile confidence intervals for AP or empirical TPR-at-FPR differences. These intervals condition on fitted models and do not capture training variability or traffic-group dependence. Per-seed predictions, configurations, thresholds, and provenance remain available for verification. Together, these layers support method comparisons that consider missed attacks, false alarms, uncertainty, and resource requirements alongside aggregate discrimination.

## Table 3 Explanation

Table 3 connects each evaluation layer to a distinct operational question. Overall classification measures describe decisions at a chosen threshold, whereas ranking measures describe discrimination across thresholds. Operating-point measures relate detection to false alarm constraints, attack-family recall identifies uneven coverage, and cost measures establish resource requirements. These layers should therefore be interpreted jointly rather than treated as interchangeable summaries. A method with strong aggregate performance may still miss rare attacks, generate excessive alerts, or require greater computational resources. Apparent advantages must also be assessed against seed variability and uncertainty in paired comparisons.
