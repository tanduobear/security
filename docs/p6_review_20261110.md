## P5新增结果的实际核对

五个种子的Test文件哈希、预测行ID及顺序、真实标签和攻击族均与P6对应Test数据一致。保存的二元预测与固定阈值一致；AP和ROC-AUC从保存分数复算也一致。这些检查支持P5新增预测的可追溯性，不代表已验证从头重训或八配置搜索。

P3完整校验仍失败。直接执行以下只读命令可复现：

```powershell
& $p6python -m eval.validate .tmp/p5-review/results/p3_m2_records/m2_seed42.json
```

实际错误为ValueError: ROC threshold sentinel is invalid。五份记录的ROC首阈值都使用了有限数，P3规定该无报警端点应为null。

另外，导出脚本calculate_curves使用drop_intermediate=True裁剪ROC点，但保存完整PR阈值；这不符合P3校验器要求的ROC/PR阈值序列对应关系。例如seed42的ROC阈值数为39330，PR阈值数为231209，无法通过该一致性要求。

逐一按相同target_fpr比较还发现五个操作点与P3规则不同：seed42的5%、seed44的5%、seed45的1%、seed46的1%和5%。新导出脚本在相同最大TPR的候选中取最后一个点，而P3优先最低FPR。此处主要是接口与并列选择约定不同，不据此宣称AP或AUC错误。

建议P5直接调用eval.metrics.compute_curves和tpr_at_fpr，使用原有保存分数重新导出五份记录，再通过eval.validate的结构与数值校验。无需因这些导出问题重训模型。不要手改计算出的指标或仅把首阈值替换为null来绕过检查。
